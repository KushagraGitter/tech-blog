Tree of Thoughts: When AI Tries Multiple Paths at Once

October 11, 2026 · 5 min read
AIReasoningPlanning

Chain-of-Thought showed that step-by-step reasoning works. But here's the catch: what if you make a mistake in step 2? You're stuck on the wrong path.

Tree of Thoughts fixes that by letting the AI explore multiple reasoning paths and backtrack when one hits a dead end.

Linear vs. Branching Reasoning

Chain-of-Thought (linear):

Step 1: Start here
Step 2: Do this (locked in)
Step 3: Do that (stuck if step 2 was wrong)
Answer: Wrong

Tree of Thoughts (branching):

Step 1: Start here
Step 2a: Try this path
Step 2b: Try that path
Step 2c: Try another path

If 2a fails → backtrack and explore 2b
If 2b works → continue with 2b
Answer: Right

The Problem ToT Solves

Imagine you're solving a complex puzzle. You go down one path, realize it's wrong, but a linear chain-of-thought agent can't backtrack. It's committed to its path.

Tree of Thoughts says: "Generate multiple next steps. Evaluate which ones look promising. Keep exploring the best ones. If one fails, try the next."

How It Works

Three ingredients:

  1. Generate candidates: For each step, the model generates 3-5 possible next moves (not just 1).
  2. Evaluate candidates: Quickly evaluate which moves look good (do they seem on track?) and which look bad.
  3. Explore promising branches: Expand only the paths that look promising. Abandon the rest.

Example: Solving a Sudoku puzzle

Current state: Half-filled grid

Option A: Fill cell 1,1 with 5 (seems valid)
Option B: Fill cell 1,1 with 3 (seems valid)
Option C: Fill cell 1,1 with 7 (conflicts with row — bad)

Pursue A and B. Abandon C.

For A: Option A1, A2, A3 (keep going)
For B: Option B1, B2 (one leads to contradiction, backtrack)

...continue until solved.

Why It's Better Than Chain-of-Thought

CoT strength: Simple, fast, works for many tasks.

ToT strength: Explores the space of possible solutions, can correct mistakes, finds better answers to hard problems.

The trade-off: ToT uses way more tokens (you're generating and evaluating multiple branches), so it's slower and more expensive. Use CoT for simple questions, ToT for hard problems.

Real-World Applications

  • Planning: "Plan my day" — explore different orderings of tasks, evaluate which schedule is best.
  • Game playing: Chess, Go, or game strategy where you need to look ahead multiple moves.
  • Math competitions: Hard math problems where you might go down wrong paths.
  • Code debugging: Explore multiple hypotheses about why code is broken, evaluate each one.
  • Creative writing: Plot multiple story branches, evaluate which is most compelling.

The Limit: Search Depth

Tree of Thoughts scales exponentially. If each step has 3 options and you explore 10 steps with full branching, you've got 3^10 = 59k paths to explore. That's a lot of tokens.

So in practice, ToT systems use aggressive pruning: evaluate branches harshly, kill bad ones early, only expand the top few.

Modern Variants

Newer systems use ToT ideas but with different search strategies:

  • Best-first search: Explore the most promising branch fully before trying others.
  • Beam search: Keep the top K branches alive at each step.
  • Monte Carlo tree search: Randomly sample branches, then exploit the good ones.

What You Take Away

  • Linear reasoning (CoT) can get stuck.
  • Branching reasoning (ToT) can explore and backtrack.
  • Use ToT for hard problems with multiple plausible paths.
  • Use CoT for simple, straightforward tasks (it's cheaper).
  • The best system often combines both: quick CoT for filtering, deep ToT for hard cases.
