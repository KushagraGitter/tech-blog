Toolformer: Teaching AI When to Call APIs

October 11, 2026 · 5 min read
AIToolsAPIs

ReAct showed that AI can act. But there's a bigger question: How does an AI learn which tool to call and when?

Toolformer answers that by letting the model train itself on its own tool calls.

The Problem: Humans Were Deciding

With ReAct, a human has to manually decide what tools are available and explicitly tell the model "Here are your options: search, calculator, database." The model picks from a curated menu.

But what if the model could learn when to use tools automatically? What if it could figure out "I need a calculator here" or "I need to search the web here" on its own?

Toolformer's Insight

Meta researchers (Schick et al., 2023) trained a model to use tools by:

  1. Let it generate tool calls: The model learns a special syntax like [CALCULATOR(2+2)] embedded in its output.
  2. Execute those calls: When the model outputs that syntax, you actually run the tool and return the result.
  3. Self-supervise: The model checks if the tool call helped improve its answer. If it did, keep it. If it didn't, ignore it.

Example:

User: "What's 47 × 83?"

Model generates: "I need to calculate this. [CALCULATOR(47 × 83)] = 3901. So the answer is 3901."

Then the model checks: "Did calling the calculator make my answer better? Yes, because I was right." So it learns to use it in future math problems.

Why This Is Better Than ReAct

ReAct: A human tells the model what tools exist. The model picks from the menu you gave it.

Toolformer: The model learns which tools help it, and trains itself to use them at the right moments.

Toolformer is more autonomous. It doesn't need someone to say "You can use a calculator." It learns "I should use a calculator when there's a math problem."

The Trade-Off

Toolformer wins on:

  • Generalization (the model learns deep patterns about when tools help)
  • Autonomy (no manual tool curation needed)
  • Scalability (it learns from lots of tools at once)

ReAct still wins on:

  • Control (you decide exactly what's available)
  • Safety (you can restrict what an untrusted model calls)
  • Simplicity (no training needed)

Real-World Impact

In practice, modern systems use a hybrid:

  • Give the model a menu of tools (ReAct-style)
  • Let it learn through in-context examples how those tools help (Toolformer-style)
  • Let it self-correct if a tool call didn't work

This is how ChatGPT's "code interpreter" and Claude's "tool use" actually work — curated tools + learned patterns of when to use them.

The Open Question

Toolformer trains on simple tasks. What happens when you scale it to thousands of tools? Or when tools have unintended side effects? That's still being researched.

There's also a safety question: If a model learns to use tools autonomously, what stops it from using them in ways you didn't intend?

What You Take Away

  • APIs are data. Models can learn when to call them.
  • Self-supervision (the model checking if its own actions helped) is powerful and cheaper than human labeling.
  • The best systems combine explicit tool curation with learned tool patterns.
  • The model needs feedback (did the tool call help?) to learn, not just permission to call tools.
